## 어떤 문제를 푸는가

대행사에서 체험단 원고를 검수하는 일은 대체로 이렇게 굴러갑니다.

크리에이터가 워드나 파워포인트로 원고를 보냅니다. 담당자는 캠페인 가이드를 옆에 띄워 놓고 한 줄씩 대조합니다.

제품명 표기가 맞는지, 필수 해시태그가 다 들어갔는지, 광고 고지가 상단에 있는지, 기능을 언급했으면 따라와야 할 고지 문구가 붙었는지 확인합니다.

5명분 합본이면 이 과정을 5번 반복하고, 원고 파일에 코멘트를 달아 다시 보냅니다.

이 과정에서 사람이 판단해야 하는 건 사실 얼마 되지 않습니다. 대부분은 **“가이드에 적힌 것과 같은지”를 확인하는 대조 작업**입니다.

그런데도 시간이 오래 걸리고, 반복하다 보면 놓칩니다.

검대리는 이 대조 작업만 떼어내 자동화합니다.

**판단은 여전히 사람이 합니다.**

## 기존 서비스와 다른 점

|  | 기존 인플루언서 플랫폼 | 검대리 |
|---|---|---|
| 범위 | 섭외 → 계약 → 정산 전 과정 | 검수 한 단계만 |
| 원고 | 플랫폼 안에서 작성 | 워드·PPT·엑셀 파일 그대로 |
| 결과 | 플랫폼 안에 코멘트 | 원본 파일에 기입해서 반환 |
| 가입 | 필요 | 없음 |
| 원고 전송 | 서버로 업로드 | 브라우저 밖으로 나가지 않음 |

플랫폼을 쓰지 않고 파일로 일하는 팀을 위한 도구입니다.

대기업 IMC 캠페인일수록 워드와 파워포인트로 굴러갑니다.

## 왜 HTML 파일 하나인가

이건 취향이 아니라 제약에서 나온 결론입니다.

회사 PC에는 프로그램 설치 권한이 없는 경우가 많습니다. 새 웹 서비스를 쓰려면 보안 검토를 통과해야 하고, 클라이언트의 미공개 제품 정보가 담긴 원고를 외부 서버에 올리는 것도 조심스럽습니다.

설치도 서버도 없이, 브라우저만으로 동작하게 만든 이유입니다.

그래서 이런 선택을 했습니다.

- **라이브러리 0개**  
  ZIP 해석, Office XML 파싱, 워드 코멘트 삽입을 직접 구현했습니다. 브라우저에 내장된 `DecompressionStream` / `CompressionStream`을 씁니다.

- **CDN 의존 최소화**  
  Tailwind 같은 CSS 프레임워크를 CDN으로 불러오지 않습니다. 폰트와 아이콘만 CDN을 쓰되, 끊겨도 기본 폰트로 폴백되게 했습니다.

- **파일 하나로 배포**  
  받은 사람은 HTML 파일을 더블클릭하면 됩니다.

결과적으로 규칙 기반 검수는 인터넷이 없어도 돌아갑니다.

원고가 서버로 나가지 않으니 외부 서버 업로드를 전제로 한 보안 부담도 줄였습니다.

이게 이 도구의 가장 큰 장점입니다.

AI 검수만 예외입니다. 사용자가 자기 API 키를 넣거나, 프롬프트를 복사해 회사에서 승인한 AI에 직접 붙여넣는 방식 중에 고르게 했습니다.

## 설정 구조

검수 기준을 바뀌는 주기에 따라 세 층으로 나눴습니다.

매번 다시 입력하는 항목을 최소화하기 위해서입니다.

| 구분 | 무엇 | 언제 바꾸나 |
|---|---|---|
| A층 · 기본 검수 항목 | 어느 캠페인에나 들어가는 항목 | 거의 안 바꿈. 필요 없으면 토글로 끔 |
| B층 · 캠페인 설정 | 제품명 사전, 해시태그, 고지 문구, 플랫폼 기준, 미션 프리셋 | 캠페인 시작할 때 한 번 |
| C층 · 콘텐츠 정보 | 이번 콘텐츠의 주제와 키워드 | 콘텐츠마다 |

설정은 브라우저에 자동으로 저장되고, 파일(JSON)로 내보내 팀에 공유할 수 있습니다.

팀 전체가 같은 기준으로 검수하게 됩니다.

## 미션 프리셋 — 플랫폼 × 회차 × 유형

가이드 한 부에 여러 플랫폼이 섞여 있고 플랫폼마다 회차 수가 다른 경우가 많습니다.

유튜브는 단발성인데 블로그·인스타는 3회차인 식입니다. 인플루언서 유형(펫·커플·1인가구)에 따라 담을 내용이 갈리기도 합니다.

축이 셋이라 화면을 셋으로 나누면 감당이 안 되므로 한 표에 담고, 검수할 때 플랫폼과 유형으로 좁혀서 고르게 했습니다.

해당 없는 칸은 비워 두면 전체 공통으로 처리하므로, 축을 안 쓰는 단순한 캠페인은 회차만 적으면 됩니다.

### 플랫폼은 사용자가 정의합니다

블로그·인스타그램·유튜브가 코드에 박혀 있지 않습니다.

행을 추가해서 직접 만듭니다.

| 플랫폼 | 별칭 | 최소 글자 | 이미지 | 영상 | 광고 고지 |
|---|---|---:|---:|---:|---|
| 블로그 | 블로그, 커뮤니티 | 3,000 | 15 | 0 | 문구 · 확인 범위 |
| 인스타그램 | 인스타, 릴스 | 800 | 6 | 1 | 문구 · 확인 범위 |
| 영상 기획안 | 유튜브, 틱톡, 쇼츠 | 500 | 0 | 1 | 문구 · 확인 범위 |

파일 형식과 플랫폼은 아무 관계가 없습니다.

블로그 원고를 파워포인트로 쓰는 곳도, 영상 기획안을 엑셀로 쓰는 곳도 있습니다.

형식은 **“어떤 파서로 읽을지”**만 정하고, 플랫폼은 **“어떤 기준으로 검사할지”**만 정합니다.

파일 형식으로 플랫폼을 추측하지 않습니다. 회사마다 달라서 틀릴 확률이 높고, 틀린 추천은 없느니만 못하기 때문입니다.

## 검수 방식

### 기계 검수 — 오프라인, 무료, 확정적

규칙으로 판정할 수 있는 것만 봅니다.

같은 입력에 항상 같은 결과가 나옵니다.

- 제품명 표기
- 필수 / 택1 해시태그
- 광고 고지 유무
- 최소 글자·이미지·영상 수
- 타 브랜드 언급
- 최상급 표현
- 필수 고지 문구 누락과 중복
- 사용자가 직접 만든 규칙

### AI 검수 — 판단이 필요한 것

- 맞춤법
- 주제 부합
- 법무 리스크
- 기능 설명 오류
- 광고 고지 표기 방식
- 말투

AI가 기계의 오탐을 걸러냅니다.

응답의 `dismiss` 배열에 담긴 항목은 취소선 처리됩니다.

기계는 넓게 잡고 AI가 좁히는 구조입니다.

그래도 틀릴 때가 있으므로 검수자가 결과에서 지적을 직접 뺄 수 있습니다.

뺀 항목은 판정 계산과 검수본 파일에서 함께 제외되고, 다시 되살릴 수도 있습니다.

## 결과

티어 1(게재 불가) / 2(수정 필요) / 3(권고)로 나누고 판정 도장을 찍습니다.

- **워드**  
  문서 앞에 요약을 붙이고, 위반 문구가 있는 문단에 코멘트를 삽입합니다. 기존 코멘트는 보존됩니다.

- **파워포인트**  
  본문 셀 끝에 검수 의견을 덧붙이고, 이미지 지적은 해당 슬라이드 수정요청 칸에 넣습니다.

- **엑셀**  
  각 시트 오른쪽에 「검수 의견」 열이 붙고, 「검수 결과」 시트가 하나 추가됩니다. 셀 코멘트는 그리기 객체까지 손대야 해서 파일이 깨지기 쉬워 이 방식을 택했습니다.

- **사진·영상 속 내용**  
  이 도구가 직접 볼 수 없습니다. 체크리스트를 띄워 사람이 직접 확인하고, 체크한 것만 파일에 반영됩니다.

- **검수 이력**  
  CSV로 내보낼 수 있습니다.

## 지원 형식

| 형식 | 가이드 | 원고 | 검수본 출력 |
|---|---:|---:|---|
| `.docx` 워드 | ○ | ○ | ○ 코멘트 삽입 |
| `.pptx` 파워포인트 | ○ | ○ | ○ 셀 기입 |
| `.xlsx` 엑셀 | ○ | ○ | ○ 검수 의견 열 + 요약 시트 |
| `.hwp` / `.hwpx` 한글 | ✕ | ✕ | ✕ |
| `.pdf` | ✕ | ✕ | ✕ |

한글 문서는 워드(`.docx`)로 저장해서 올려 주세요.

PDF는 텍스트 추출에 외부 라이브러리가 필요해 오프라인 원칙과 충돌하므로 지원하지 않습니다.

## 해결한 문제들

만들면서 부딪힌 것 중 기록해 둘 만한 것들입니다.

### 표를 텍스트로 뭉개면 안 된다

한국 캠페인 가이드는 고지 문구·표기법·미션이 전부 표에 들어 있습니다.

표를 그냥 텍스트로 읽으면 “이 문구가 어느 기능에 붙는 건지”가 사라집니다.

그래서 표 머리말을 읽어 열 단위로 역할을 물려주는 방식으로 파싱합니다.

머리말 단어는 회사마다 다르므로 설정에서 직접 정할 수 있게 했습니다.

### 한글 어절 경계

`인스타그램`이라는 단어에서 `그램`이 검색에 걸립니다.

앞 글자가 한글이면 제외하는 처리가 필요했습니다.

### 해시태그는 붙여 씁니다

`#래온셀배리어크림`은 제품명 표기 위반이 아닙니다.

표기 검사에서 해시태그를 제외합니다.

### 파워포인트는 한 문장이 여러 조각으로 쪼개집니다

글자 하나만 굵게 처리해도 서식 단위로 분할되어 문자열 검색이 실패합니다.

문단 단위로 합쳐서 읽습니다.

### AI가 JSON 예시값을 그대로 베낍니다

출력 형식을 예시로 보여주면 그 설명 문구를 값으로 채워 답하는 경우가 있습니다.

가이드 원문에 없는 값은 버리는 방어가 필요했습니다.

### 5인 합본은 사람마다 결과가 달라야 합니다

슬라이드에서 사람 구분자를 찾아 나누고, AI 프롬프트에도 사람별 구분자를 넣어 `person` 값으로 결과를 배분합니다.

구분 방식은 회사마다 다르므로 여러 패턴을 봅니다.

### 제품명 변형을 자동 생성합니다

정식 표기 한 줄만 넣으면 대소문자·띄어쓰기·철자 뒤바뀜 조합을 만들어 탐지합니다.

### Office 파일은 한글을 숫자 참조로 저장하기도 합니다

`&#50476;` 같은 형태를 풀지 않으면 표 머리말을 못 읽어 열 역할 판정이 통째로 실패합니다.

### 사람을 못 나누면 중복 검사가 남의 원고를 잡습니다

자동 인식이 실패하면 여러 명의 원고가 한 덩어리가 되고, 그 상태로 중복을 세면 다른 사람 문구가 중복으로 잡힙니다.

그래서 검수자가 각 부분의 작성자를 직접 지정할 수 있게 하고, 지정하지 않으면 중복 지적을 위반이 아니라 확인 요청으로 낮춥니다.

AI가 사람을 구분해 내면 그 기준으로 결과를 다시 나눕니다.

### 고지 문구 표기는 설정으로 풀 문제가 아니었습니다

처음에는 사용자가 기호를 정하게 했는데, 정한 것과 다르게 쓰는 순간 못 찾고 “안 쓴다”고 하면 아예 못 찾았습니다.

지금은 흔히 쓰는 괄호와 기호를 전부 보고, 기호가 없는 문장은 말투로 판별합니다.

### 기계는 “짝지어져 있다”는 것만 압니다

가이드 표에서 기능↔고지 문구를 뽑을 때 「추가 콘텐츠 업로드 시」 같은 운영 안내가 기능명 자리에 딸려 들어옵니다.

조건·시점·행동을 가리키는 말을 걸러 내고, AI가 사전 자체를 다시 만들어 덮어쓰게 했습니다.

### 검수본을 만들 때 사진을 다시 압축하면 안 됩니다

우리가 고치는 건 글이 든 XML 몇 개뿐인데, 예전에는 사진과 동영상까지 압축을 풀고 검사값을 새로 계산했습니다.

20MB짜리 원고에서 화면이 몇 초씩 멈췄고, 게다가 미디어가 압축되지 않은 채 다시 담겨 파일이 원본보다 커졌습니다.

지금은 손대지 않은 항목을 압축된 그대로, 원본 검사값과 함께 옮깁니다.

**20MB 원고 기준 0.4초입니다.**

### `ch` 단위는 한글에서 절반이 됩니다

`max-width:88ch`가 한글로는 44자여서, 화면에 공간이 남는데도 문단이 일찍 줄바꿈됐습니다.

### 가이드를 말없이 자르면 안 됩니다

프롬프트에 넣을 때 앞부분만 보내던 탓에, 뒷부분에만 있는 내용을 AI가 “가이드에 없다”고 판단했습니다.

지금은 통째로 보내고, 그래도 한계를 넘으면 몇 자가 빠졌는지 화면에 알립니다.

### AI 판단으로 기계 결과를 통째로 덮으면 손해가 큽니다

처음에는 AI가 만든 고지 문구 사전으로 기계 결과를 대체했는데, 맞게 뽑힌 것까지 한 번에 날아갔습니다.

지금은 AI가 “이건 틀렸다”고 짚은 것만 빼고 나머지는 유지한 뒤, AI가 새로 찾은 것을 더합니다.

## 저장소 구조

이 저장소에는 검대리의 공개 평가용 소스, 샘플 자료, 테스트 코드 및 배포 파일이 포함되어 있습니다.

```text
src/        애플리케이션 소스
sample/     공개 테스트용 가상 캠페인 자료
test/       회귀 테스트
.github/    CI 및 GitHub Pages 배포 설정
index.html  GitHub Pages 실행 파일
```

소스는 구현 방식과 동작 구조를 확인할 수 있도록 공개되어 있습니다.

**수정, 파생작업, 재배포, 미러링 및 상업적 이용은 허용되지 않습니다. 자세한 내용은 LICENSE를 확인해 주세요.**

### 공개 테스트 자료

`sample/` 폴더에는 기능 확인을 위한 공개 테스트용 가상 브랜드 캠페인 자료가 포함되어 있습니다.

실제 클라이언트 자료는 포함하지 않습니다.

### 저장소 자동화

- `.github/workflows/ci.yml`  
  저장소의 빌드 및 회귀 테스트 검증에 사용됩니다.

- `.github/workflows/pages.yml`  
  원본 프로젝트의 GitHub Pages 배포에 사용됩니다.

- `package.json`  
  저장소 내부의 테스트 환경을 위한 최소 설정입니다.

이 저장소에는 실제 클라이언트 자료나 API 키를 포함하지 않습니다.

`sample/`은 공개 테스트용 가상 브랜드 자료입니다.
